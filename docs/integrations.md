# Integrations

A workspace connects an account at another service once (a Hetzner Cloud project, a DigitalOcean team, a Cloudflare account) and the rest of the panel uses it. This page is for contributors adding a provider. Hetzner Cloud is the reference: `app/Support/Integrations/Hetzner/`.

## How it fits together

| Piece                                           | Where                         | What it does                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `integrations` table, `App\Models\Integration`  | one row per connected account | `provider` (catalogue key), `label`, `credentials` (cast `encrypted:array`, `#[Hidden]`), `fingerprint` (keyed hash, so one account isn't connected twice), `meta` (what the provider said, never secrets), `status` (`connected` or `failing`), `last_checked_at`, `last_error`, `created_by`. A workspace can hold several accounts of one provider unless `multipleAccounts()` says no. |
| `App\Support\Integrations\Provider`             | the contract                  | Connect form fields, `verify()`, capabilities, a summary line.                                                                                                                                                                                                                                                                                                                             |
| `App\Support\Integrations\ProviderClient`       | the HTTP base                 | Timeouts (15 s, 5 s to connect), three tries on 429 and 5xx, every failure turned into `IntegrationFailed` with a message a person can act on.                                                                                                                                                                                                                                             |
| `App\Support\Integrations\IntegrationProviders` | the registry                  | Built-in providers are registered in its constructor. A package can call `app(IntegrationProviders::class)->register(new MyProvider)` from its service provider.                                                                                                                                                                                                                           |
| `IntegrationCatalogue`                          | the Integrations page list    | Every row on the page. A provider's `key()` must match its catalogue key; the row then shows Connect, opens the connect dialog, and Manage goes to the account page.                                                                                                                                                                                                                       |
| `WorkspaceIntegrations`                         | page props                    | Adds each registered provider's accounts to the page and to the Connected rail.                                                                                                                                                                                                                                                                                                            |
| `IntegrationAccountController`                  | routes                        | `workspace.integrations.connect` (POST `integrations/connect/{provider}`), `.show` (the account page), `.check`, `.update` (rename), `.destroy` (disconnect).                                                                                                                                                                                                                              |

Cloud providers (anything with servers) also implement `App\Support\Integrations\Servers\ManagesServers`, and get the rest for free:

| Piece                                                                                               | What it does                                                                                                                                                                                                                                |
| --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `integration_servers`, `IntegrationServer`                                                          | The account's servers as last seen (`details` is `Server::toArray()`), and the machine each one is (`machine_id`, unique).                                                                                                                  |
| `CloudServers::sync()`                                                                              | Lists the servers, keeps them, drops vanished ones, and links servers to machines by public IPv4 or an address in their IPv6 network. Runs on connect, on Check again and when the account page loads its servers.                          |
| `CloudServers::claim()`                                                                             | Called from `DaemonEnrolController` when a daemon joins: a server made from ServerOS becomes that machine (by its join token), and an imported one is linked by address.                                                                    |
| `integration_operations`, `IntegrationOperation`, `ServerOperations`, `AdvanceIntegrationOperation` | Changes that take several calls (make a server, resize one). Each step waits on the provider's action, then the job dispatches itself again with a delay. Nothing blocks a page; the dialogs poll `workspace.integrations.operations.show`. |
| `CloudServerController`                                                                             | `server-options` (locations, types with prices, images, SSH keys) and making a server.                                                                                                                                                      |
| `MachineServerController`                                                                           | Restart, power cycle, resize types and resize, snapshots (list, take, delete) and deleting the server, under `machines/{machine}/server/...`.                                                                                               |
| `CloudInit::userData()`                                                                             | The cloud-init a new server starts with: Docker, then the panel's join command with a fresh enrolment token.                                                                                                                                |

The machine page shows the linked server from `CloudServers::machineProps()` (`cloudServer` prop on `MachineShow` and `MachineSettings`), and the dialogs live in `resources/js/components/machines/server/`.

## Adding a provider

1. **Catalogue.** Make sure `IntegrationCatalogue::all()` has the row and its `logo` exists in `BrandLogo`. Its key is your provider's `key()`.
2. **Client.** Extend `ProviderClient` with `baseUrl()`, `providerName()` and `headers()`. Override `providerMessage()` to pull the API's own error text, and `failure()` for codes worth their own words (a read-only token, a project limit). Use only documented endpoints. Paginate with a loop like `HetznerClient::all()`.
3. **Provider.** Extend `Provider`:
    - `key()`, `name()`.
    - `fields()`: a `ConnectField` per input. `secret: true` fields render as password inputs and are never sent back. Give `help` (where to click to make the token, and the least access it needs), `link` (the page where it's made) and `rules`.
    - `verify(array $credentials)`: one cheap read that proves the credentials reach an account. Return `new ConnectedAccount($suggestedLabel, $meta)`. `meta` is shown and kept in plain JSON, so only names and counts. Throw `IntegrationFailed` (the client already does) and its message becomes the form error.
    - `capabilities()`: `Capability` cases. Add a case (with its label and description) when you need a new one.
    - `summary()` for the Connected rail, `facts()` for the account page.
4. **Servers (cloud providers).** Implement `ManagesServers`. Map the provider's objects to `Server`, `ServerType` (prices per location, the locations it can be made in now), `ServerImage` (mark one `recommended`; Ubuntu LTS where there is one), `SshKey`, `Snapshot`. Methods that start something return the provider's action id, or `null` when it's already done; `action()` turns an id into `ActionState`. Say whether `resizeNeedsPowerOff()`. Filter `resizeTypes()` to what the provider accepts (same architecture and storage, a disk at least as big).
5. **Register** it in `IntegrationProviders::__construct()` (or from a package).
6. **Copy.** Every string a person reads goes through `__()` / `$t()`. Plain and short, no em dashes.
7. **Tests.** A fake of the API in `tests/Support/` like `FakeHetzner` (it keeps servers, actions and snapshots, records calls, can fail the next call to a path), installed with `Http::fake()` and `Http::preventStrayRequests()`, so no test reaches the real API. Cover at least: connect success and refused credentials, credentials absent from props and Activity, permissions, linking by address, each action's request body, and a failure that leaves things as they were. `Sleep::fake()` keeps the retry waits instant.

## Rules

- **Credentials stay on the server.** Never put `$integration->credentials` in props, JSON, logs, Activity meta or exception messages.
- **Permission.** Everything uses `manageMachines` unless a capability needs more. Check `$integration->workspace_id === $workspace->id` in every action: `{integration}` is not scoped to the workspace by the router.
- **Audit.** Every write route is `#[Audited]` and records an `Activity` (or calls `AuditContext::nothingChanged()`). Add an `ActivityLine` entry for each action; `integration.*` is in the "Workspace and billing" group, server actions are `machine.server_*` and `machine.snapshot_*`.
- **Never block a page.** Short calls (a restart, a snapshot) run in the request with the client's timeouts. Anything that waits on the provider runs as an `IntegrationOperation`.
- **Leave things as they were on failure.** A resize that stopped the server starts it again before giving up; a server that couldn't be made gives its join token back.
- **Cache arrays, not objects.** `cache.serializable_classes` is off, so a cached object comes back as `__PHP_Incomplete_Class`. Cache `toArray()` and rebuild (see `ServerPlans::fromArray()`).
- **POSTs aren't retried after a server error,** only when the provider turned them away unread (429), so nothing is made twice.
- **If the catalogue key already has a state** from elsewhere in the panel (Cloudflare tunnels, PagerDuty workflow steps), merge it in `WorkspaceIntegrations::accounts()` instead of replacing it.
